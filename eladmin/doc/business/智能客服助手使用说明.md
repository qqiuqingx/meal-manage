# 智能客服助手使用说明

## 运营统计问答

助手支持在当前客服权限范围内查询聚合运营数据，例如“今天待核销客户有多少”“今天已排餐客户有多少”“活跃客户有多少”“未来七天到期订单有多少”。

- “今天还有多少客户”“剩下的客户有多少”“没完成的客户还有几个”等未说明待办口径的问法，都会先询问待排餐、待配送或待核销，避免采用错误口径。
- 支持同日期、同数据源的少量指标组合，例如“今天午餐已排餐和待核销客户分别多少”，也支持“今天待排餐客户按套餐分组”“今天待核销客户按来源分组”。单次最多 3 项、最多两个分组维度，只使用登记指标并复用一次每日工作量聚合；活跃客户、到期订单等不同数据源不会被自动混合成同一报表。
- 统计卡片展示总数、日期、餐次、口径版本、时区和查询时间；不展示客户明细、手机号、地址或金额。
- 日期缺失时，按口径需要补充日期；“今天”“昨天”“本周”等表达按 `Asia/Shanghai` 时区解析。

## 多轮追问与澄清

助手会在同一会话中保留经过工具事实确认的客户、订单、日期和餐次焦点，但每一轮实时问题都会重新查询业务数据。例如：

```text
客服：B3303 今天午餐排了吗？
助手：……
客服：那晚餐呢？
助手：沿用客户 B3303 和当天，只将餐次切换为晚餐后重新查询。
客服：最近核销呢？
助手：沿用客户 B3303，但不会把上一轮的“晚餐”强行套用到未指定餐次的核销历史；如缺少范围会继续澄清。
```

当问题缺少客户、日期或餐次时，响应状态为 `NEED_MORE_INFO`，页面会显示缺失条件和受控快捷回复。快捷回复没有客户编号、套餐或规则主题等固定选项时不会伪造按钮。

姓名匹配多个客户时会展示候选表，客服点击包含正确 `customerCode` 的“选择”按钮继续查询；不会按第一条记录自动选择，也不会使用内部 ID 或姓名拼接查询。

## 失败重试、跳转与展示层级

- 网络或 Agent 暂时失败时，助手消息提供“重试”；重试沿用原问题文本但使用新的消息幂等键，不新增重复的用户气泡。
- “客户档案”“客户订单”“排餐详情”跳转由前端固定业务路由生成，只携带受控客户编号、订单编号、日期和餐次；助手响应不能提供任意路由。
- 复制只包含面向客服的结论文本，不包含工具事实、模型名称、规则摘要、内部 URL 或技术 JSON。
- 默认页面只显示业务结论、业务卡片、查询时间和业务告警；工具调用、稳定告警码和模型/规则信息收纳在可手动展开的“技术详情”中。
- 归档会话可以打开查看历史卡片和澄清状态，但不能发送、重试或选择候选；点击“恢复会话”后才恢复可写能力。

## 适用对象

仅供已登录且拥有 `agentDiagnosis:list` 及对应业务权限的内部客服使用。助手有 12 个只读工具；功能灰度开启且客服具有 `customerProfile:add` 或 `customerOrder:add` 时，还可保存辅助表单草稿。草稿不是正式客户或订单，助手不会自动提交、修改、删除、重排餐、核销或退餐。

## 客户和订单辅助草稿

客服可在对话中提供新增客户 + 首单资料，或为已有客户提供新增订单资料。助手会提取已识别字段、列出缺失项，并处理关键歧义：同名客户、套餐、子套餐、换菜菜品或试餐订单有多个候选时必须继续确认，不能自动选第一条。

- `EDITABLE`：草稿已保存但仍缺必填字段或有阻断歧义，可继续在原会话补充、修订。
- `READY`：卡片显示固定“去新建客户”或“去新增订单”按钮。点击后由业务页面领取草稿、预填现有表单；客服必须核对并手动提交。
- `CLAIMED`：已经在业务页面领取，刷新或返回后仍可继续编辑，但同一版本只能成功提交一次。

对话纠正和“转为新建客户”动作只提交草稿引用，不在浏览器或 URL 中携带完整资料。主系统会按当前客服和会话重新读取活动草稿，再把当前版本交给 Agent 乐观锁修订；领取使用行锁，避免与同时发生的对话修订互相覆盖。
- `SUBMITTED/EXPIRED`：按钮禁用；已提交草稿不再暴露 payload，未提交草稿默认 24 小时过期并清空敏感 payload。

“已有客户新增订单”必须唯一匹配当前数据范围内的客户。未找到客户时，订单草稿卡片可显示固定“转为新建客户”对话按钮；点击后只发送固定业务语句，由 Agent 重新保存 `CREATE_CUSTOMER_WITH_ORDER` 草稿并复用对话资料，不直接打开订单页面。多匹配时必须先选择客户。首期不支持图片、草稿转交或自动提交，也没有独立草稿审计页面。返回原对话时使用固定会话标识，不接受助手生成的任意 URL。

## 常用问法

- `B3303 目前什么情况？`
- `B3303 还有多少餐？`
- `B3303 有哪些订单？`
- `订单 O20260711001 什么情况？`

订单卡片会显示关联排餐、核销和退餐记录数量。数量仅用于快速判断是否存在关联业务记录；需要查看具体核销、退餐或排餐内容时，应继续追问对应明细。
- `B3303 今天午餐排了吗？`
- `B3303 今天午餐菜里有什么配料？`
- `B3303 最近核销记录`
- `B3303 最近退过餐吗？`
- `B3303 签了什么套餐？`
- `午餐核销扣哪个池？`
- `B3303 今天午餐已排餐但未核销吗？`
- `今天的菜单是什么？`

## 查询边界

- 支持客户、订单、排餐、核销、退餐、套餐、菜品配料、按客户饮食限制过滤的候选菜预览和已配置业务规则的查询。
- 订单金额、单价、优惠、已收、退款金额和餐费余额均不提供；询问相关内容时会明确拒绝，不会调用金额服务。
- 手机号和配送地址默认脱敏。
- 为填写草稿而主动提供的完整手机号和地址会进入模型、本人会话原文和 24 小时草稿 payload；不会显示在草稿卡片、工具追踪或普通日志中。请勿提供表单无关的敏感信息。
- 姓名可能匹配多个客户时，客服需从候选中选择；助手不会自行确定客户。
- 排餐、菜品和历史记录查询需要明确客户、日期或餐次时，助手会追问，避免无界历史查询。
- 查询公共排期菜单时只需日期，不需要客户信息；“今天”“明天”等相对日期会按当前日期解析。

## 权限与异常提示

- 仅有助手入口权限不代表拥有客户、订单、排餐、菜品等数据权限。
- 无权限时，不会以“对象不存在”替代权限错误，也不应尝试通过客户/订单 ID 猜测数据。
- 结果卡片中的“截断”表示安全上限已触发；请缩小日期范围或对象范围后再次查询。
- 查询时间、事实编号和数据来源用于人工复核；关键业务判断以主系统页面和结构化事实为准。

## 排餐诊断

原“排餐未生成诊断”能力仍保留。诊断结论是辅助排查信息，客服应结合证据、客户档案、订单和排餐页面后再作业务处理。
