# 配料标签接口

## 概述

标签是配料的独立辅助标记，与一级/二级分类并列。一个配料可以有多个标签，一个标签可以被多个配料共用。标签不分层、不自动继承分类，也不负责别名解析、客户禁忌或排餐过滤。

标签管理权限为 `dishIngredientTag:list/add/edit/del`。读取标签选项还允许已有配料权限 `dishIngredient:list/add/edit`；标签新增、修改和删除始终要求对应标签权限。菜单挂在配菜管理下，SQL 不给角色默认授权。

## 标签分页查询

```http
GET /api/dish-ingredient-tags?name=清真&page=0&size=20
```

| 参数 | 类型 | 说明 |
|---|---|---|
| name | String | 标签名称模糊查询，可省略 |
| page | Integer | 零起始页码，默认 0 |
| size | Integer | 每页数量，默认 20 |

响应为 `{content, totalElements}`，`content` 中包含 `id`、`name`、`createTime`、`updateTime`。

## 新建标签

```http
POST /api/dish-ingredient-tags
Content-Type: application/json
```

```json
{"name":"清真"}
```

需要 `dishIngredientTag:add`。服务端去除名称首尾空白；名称不能为空，最多 64 个字符，按 `utf8mb4_unicode_ci` 唯一（英文大小写不敏感）。成功返回 `201 Created` 和新建对象，包含数据库生成的 `id`。

## 修改标签

```http
PUT /api/dish-ingredient-tags
Content-Type: application/json
```

```json
{"id":12,"name":"无麸质"}
```

需要 `dishIngredientTag:edit`。成功返回 `204 No Content`。标签名称冲突或标签不存在时返回 `400`。

## 删除标签

```http
DELETE /api/dish-ingredient-tags/12
```

需要 `dishIngredientTag:del`。成功返回 `200 OK`；标签仍被配料使用时返回 `400`，提示先从配料中移除该标签。标签字典未被引用时可删除。

## 配料接口中的标签字段

`DishIngredient` 的新增和修改请求可包含 `tagIds: [12, 13]`。新增时未传、`null` 或 `[]` 均表示不绑定标签；修改时未传或 `null` 表示保持现有关系，`[]` 表示清空，非空数组表示整体替换。重复ID会去重；空值、无效或不存在的标签ID返回 `400`，配料数据和关系在同一事务中回滚。

配料列表、详情以及按菜品查询均返回 `tagIds` 和 `tags`；`tags` 是 `{id, name}` 数组，无标签时两个字段均为空数组。标签更名后，查询响应使用新名称。

DDL 与菜单脚本：`eladmin/sql/20260927_ingredient_tag.sql`。执行新 SQL 后部署后端和前端，再按现有流程为具体角色分配标签权限。

### 配料页面展示方式

配料管理展示商超卡片，支持标签筛选、标签展示和导出；分类切换沿用配料分页查询的 `parentCategoryId`、`categoryId` 参数，并将 `page` 重置为 0。标签管理在页内弹窗完成，入口允许管理员或具有任一 `dishIngredientTag:add/edit/del` 权限的用户访问，写操作仍要求对应标签权限（管理员可执行全部操作），接口参数和响应不变。
