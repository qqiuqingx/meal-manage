# 客户用餐统计页面接口文档

## 订单列表

```http
GET /api/customerProfile/mealStats
```

权限：`customerProfile:list`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `customerCode` | string | 否 | 当前订单客户编号，模糊匹配 |
| `customerName` | string | 否 | 当前客户档案姓名，模糊匹配 |
| `phone` | string | 否 | 当前客户档案手机号，模糊匹配 |
| `statsMonth` | string | 否 | `yyyy-MM`；限制订单 `start_date < 次月首日` |
| `page` | int | 否 | 页码，从 1 开始，默认 1 |
| `size` | int | 否 | 每页订单数，默认 20 |

响应为 `PageResult`，分页在订单表执行，`totalElements` 按订单数统计。同一客户不同订单各占一行；一笔订单含早餐和午晚餐时仍为一行。筛选订单状态为 `status IN (1,4)`、`remaining_count > 0`；不按订单结束日期过滤。排序依次为客户编号、开始日期、成交时间和订单 ID。

每行按以下 24 个业务列顺序返回，随后保留操作列：

1. `phone`
2. `addressText`
3. `customerCode`
4. `customerName`
5. `specialRequirements`
6. `scheduleModeText`
7. `mealTypeText`
8. `specification`
9. `soupCount`
10. `breakfastCount`
11. `lunchDinnerCount`
12. `totalCount`
13. `verifiedCount`
14. `scheduledCount`
15. `remainingCount`
16. `estimatedRemainingCount`
17. `statusLabel`
18. `medicalRequirements`
19. `dealTime`
20. `postoperativeInfo`
21. `dishRequirements` / `dishRequirementsRaw`
22. `allergyTags`
23. `dietaryRestrictions` / `dietaryRestrictionsRaw`
24. `customMenuImage`

`orderId/customerId/orderCode` 是行身份和日历标题字段，不占业务列。客户共享资料读取当前客户档案；订单编号、排餐属性、餐数、成交时间和自定义菜单来自该行订单。`specialRequirements` 和 `medicalRequirements` 分开返回；`postoperativeInfo` 返回原文。

- `verifiedCount` 使用订单累计值，已含导入历史核销基数。
- `scheduledCount` 是当前订单全部有效结果行数，包含成功与失败，不区分是否核销。
- `estimatedRemainingCount = max(remainingCount - 今日成功且未核销排餐份数, 0)`；今日按服务端业务日期计算。
- 地址优先选择 `DEFAULT`，没有时依次选择 `WORKDAY`、`WEEKEND`，联系人、电话、地址按多行返回。
- 所有餐数列是订单累计/当前值，不是所选月份内新增数；本接口不返回金额字段。

## 单订单排餐日历

日历查询和保存接口、单元格来源标记、覆盖快照、权限及错误响应见[客户档案管理接口文档第 3.11 节](客户档案管理接口文档.md#311-单订单排餐日历)。日历写入始终以 URL 中的 `orderId` 为身份，并限定当前月份。
