# 配料分类接口

## 概述

配料分类采用「一级分类 → 二级分类 → 配料」结构。分类名称存储在 `dish_ingredient_category`，配料通过二级分类ID关联。一级分类的 `parent_id` 为空，二级分类必须关联已存在的一级分类。

新增接口使用 `dishIngredient:add` 权限，编辑接口使用 `dishIngredient:edit` 权限，删除接口使用 `dishIngredient:del` 权限，查询接口使用 `dishIngredient:list` 权限。

## 查询分类树

```http
GET /api/dish-ingredient-categories/tree
```

返回启用分类的树结构，一级分类包含 `children` 二级分类列表。无请求参数。

## 查询启用分类列表

```http
GET /api/dish-ingredient-categories
```

返回启用的一级和二级分类列表。

## 查询分类详情

```http
GET /api/dish-ingredient-categories/{id}
```

按分类ID查询分类实体。

## 按父分类查询二级分类

```http
GET /api/dish-ingredient-categories/parent/{parentId}
```

返回指定一级分类下启用的二级分类，按 `sort` 升序排列。

## 新增分类

```http
POST /api/dish-ingredient-categories
Content-Type: application/json
```

新增一级分类：

```json
{"name":"蔬菜","level":1,"parentId":null,"sort":10}
```

新增二级分类：

```json
{"name":"叶菜","level":2,"parentId":3}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| name | String | 必填；服务端去除首尾空白后校验非空，最多64个字符 |
| level | Integer | 必填；`1` 为一级分类，`2` 为二级分类 |
| parentId | Integer | 一级分类必须为空；二级分类必须为已有一级分类ID |
| sort | Integer | 可选；未传或 `null` 时追加到同级末尾，明确传入 `0` 时保存为0 |

成功返回 `201 Created` 和新建分类实体，包含数据库生成的 `id`。同一父分类下重名、名称无效、层级或父分类无效时返回 `400 Bad Request`。数据库联合唯一索引可兜底二级分类并发重名；一级分类的 `parent_id` 为 `NULL`，当前索引不提供一级分类并发重名约束。

## 编辑分类

```http
PUT /api/dish-ingredient-categories/{id}
Content-Type: application/json
```

```json
{"name":"绿叶菜","sort":20}
```

请求只接受 `name` 和 `sort`，分类层级及父分类不可修改。`name` 必填，校验规则与新增相同；`sort` 未传或为 `null` 时保留原排序。成功返回 `204 No Content`。分类不存在或同级重名时返回 `400 Bad Request`。

分类名称可能作为客户过敏标签参与排餐过滤。修改名称前，前端会提示已有的客户过敏标签不会自动更新；相关客户信息需由业务确认并同步维护。

## 删除分类

```http
DELETE /api/dish-ingredient-categories/{id}
```

成功返回 `200 OK`。一级分类下仍有二级分类，或二级分类下仍有关联配料时，删除被拒绝并返回 `400 Bad Request`。
