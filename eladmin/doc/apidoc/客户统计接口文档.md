# 客户统计接口

## customer-stats

获取当天不同客户人数和成功排餐份数，按套餐和餐次分组统计。

### 请求

```
GET /api/dishes/schedule/customer-stats?date=2026-04-05
```

### 响应

```json
{
  "date": "2026-04-05",
  "totalCustomerCount": 10,
  "totalServingCount": 12,
  "groups": [
    { "mealType": "LUNCH", "mealPackage": "yuezi", "mealPackageDesc": "月子餐", "customerCount": 5, "servingCount": 6 },
    { "mealType": "LUNCH", "mealPackage": "yunqi", "mealPackageDesc": "月子餐", "customerCount": 3, "servingCount": 4 },
    { "mealType": "DINNER", "mealPackage": "yuezi", "mealPackageDesc": "月子餐", "customerCount": 2, "servingCount": 2 }
  ],
  "sourceGroups": [
    { "source": "1380013", "sourceDesc": "1380013", "customerCount": 3, "servingCount": 4 },
    { "source": "1390009", "sourceDesc": "1390009", "customerCount": 7, "servingCount": 8 }
  ]
}
```

`customerCount` 为客户ID去重后的人数；`servingCount` 为成功排餐结果行数。同一客户同餐次多份时，人数计 1、份数按 `serving_no` 分别计数。

### 数据来源

| 字段 | 来源表 |
|------|-------|
| 排餐计划 | meal_plan |
| 客户排餐 | meal_plan_customer |
| 套餐 | customer_order + parent_package |
| 来源标识 | customer_profile.phone 前7位 |

## customer-source-stats

按来源统计不同客户人数和成功排餐份数。传入日期格式时按该日期所在月份统计；传入月份格式时按指定月份统计。

### 请求

```
GET /api/dishes/schedule/customer-source-stats?date=2026-04-05
```

### 响应

```json
[
  { "source": "1380013", "sourceDesc": "1380013", "customerCount": 3, "servingCount": 4 },
  { "source": "1390009", "sourceDesc": "1390009", "customerCount": 7, "servingCount": 8 }
]
```

来源统计按客户ID去重返回 `customerCount`，并按成功排餐结果行计数返回 `servingCount`。

### 数据来源

| 字段 | 来源表 |
|------|-------|
| 排餐计划 | meal_plan |
| 客户排餐 | meal_plan_customer |
| 来源标识 | customer_profile.phone 前7位 |

## customer-meal-stats

获取客户用餐统计页面的订单分页数据，一笔订单返回一行。

### 请求

```http
GET /api/customerProfile/mealStats?page=1&size=20&statsMonth=2026-10
```

权限：`customerProfile:list`。

### 查询参数

- `customerCode`：订单客户编号，模糊匹配。
- `customerName`：客户档案姓名，模糊匹配。
- `phone`：客户档案手机号，模糊匹配。
- `statsMonth`：可选，格式 `yyyy-MM`；按 `start_date < 次月首日` 筛选，不按结束日期过滤。
- `page/size`：从 1 开始的订单页码和页大小，页大小默认 20。

列表筛选订单 `status IN (1,4)` 且 `remaining_count > 0`。订单数据库分页后，再批量补充当前页客户档案、地址和统计数据；`totalElements` 按订单数计算，同客户多订单分别返回，早餐与午晚餐不拆行。排序稳定为客户编号、订单开始日期、成交时间、订单ID。

### 字段及统计口径

24 个业务列顺序为：手机号、地址、客户编号、客户姓名、特殊要求、排餐模式、餐次、规格、含汤、早餐、午晚、合计、核销、已排餐、剩余、预计剩余、状态、基本情况、成单时间、术后天数、菜品特殊要求、过敏食物、禁忌食物、自定义菜单；之后为排餐日历操作。

- `orderId/customerId/orderCode` 是行身份及日历标题字段，不作为额外业务列。
- 客户手机号、姓名、地址、特殊要求、医嘱、术后原文、饮食对象和过敏标签来自客户当前档案；订单编号、餐数、餐次、排餐模式、规格、状态、成交时间和菜单图片来自当前订单。
- `specialRequirements` 不合并医嘱；`medicalRequirements` 是医嘱原文；`postoperativeInfo` 按原文展示。
- `verifiedCount` 使用订单累计核销数，已含导入核销基数；`scheduledCount` 是有效排餐结果总行数，含成功及失败；`remainingCount` 使用订单当前剩余数。
- `estimatedRemainingCount = max(remainingCount - 今日成功且未核销排餐份数, 0)`，今日按服务端业务日期计算。
- 所有餐数为当前订单累计值，不是当前筛选月份的发生额；接口不返回金额。

单订单日历 GET/PUT、完整 `overrides` 快照及 409 冲突规则见[客户档案管理接口文档第 3.11 节](客户档案管理接口文档.md#311-单订单排餐日历)。
