# 客户统计接口

## customer-stats

获取当天不同客户人数和成功排餐份数，按套餐和餐次分组统计。

### 请求

```
GET /api/dishes/schedule/customer-stats?date=2026-04-05
```

### 响应

```json
{
  "date": "2026-04-05",
  "totalCustomerCount": 10,
  "totalServingCount": 12,
  "groups": [
    { "mealType": "LUNCH", "mealPackage": "yuezi", "mealPackageDesc": "月子餐", "customerCount": 5, "servingCount": 6 },
    { "mealType": "LUNCH", "mealPackage": "yunqi", "mealPackageDesc": "月子餐", "customerCount": 3, "servingCount": 4 },
    { "mealType": "DINNER", "mealPackage": "yuezi", "mealPackageDesc": "月子餐", "customerCount": 2, "servingCount": 2 }
  ],
  "sourceGroups": [
    { "source": "1380013", "sourceDesc": "1380013", "customerCount": 3, "servingCount": 4 },
    { "source": "1390009", "sourceDesc": "1390009", "customerCount": 7, "servingCount": 8 }
  ]
}
```

`customerCount` 为客户ID去重后的人数；`servingCount` 为成功排餐结果行数。同一客户同餐次多份时，人数计 1、份数按 `serving_no` 分别计数。

### 数据来源

| 字段 | 来源表 |
|------|-------|
| 排餐计划 | meal_plan |
| 客户排餐 | meal_plan_customer |
| 套餐 | customer_order + parent_package |
| 来源标识 | customer_profile.phone 前7位 |

## customer-source-stats

按来源统计不同客户人数和成功排餐份数。传入日期格式时按该日期所在月份统计；传入月份格式时按指定月份统计。

### 请求

```
GET /api/dishes/schedule/customer-source-stats?date=2026-04-05
```

### 响应

```json
[
  { "source": "1380013", "sourceDesc": "1380013", "customerCount": 3, "servingCount": 4 },
  { "source": "1390009", "sourceDesc": "1390009", "customerCount": 7, "servingCount": 8 }
]
```

来源统计按客户ID去重返回 `customerCount`，并按成功排餐结果行计数返回 `servingCount`。

### 数据来源

| 字段 | 来源表 |
|------|-------|
| 排餐计划 | meal_plan |
| 客户排餐 | meal_plan_customer |
| 来源标识 | customer_profile.phone 前7位 |

## customer-meal-stats

分页查询客户用餐统计，并返回查询月份内该客户需要排餐的具体日期。

### 请求

```
GET /api/customerProfile/mealStats?statsMonth=2026-04&page=1&size=20
```

### 查询参数

| 参数 | 必填 | 说明 |
|------|------|------|
| customerCode | 否 | 客户编号 |
| customerName | 否 | 客户姓名 |
| phone | 否 | 手机号 |
| statsMonth | 否 | 统计月份，格式 `yyyy-MM`；为空时排餐日历按当前月份计算 |
| page | 否 | 页码，默认 1 |
| size | 否 | 每页条数，默认 10 |

### 响应字段

### 排餐日历字段

- `scheduleDays`：当前统计行对应餐数桶的排餐日期，`BREAKFAST` 行只含早餐，`LUNCH_DINNER` 行只含午餐/晚餐。
- `baseScheduleDays`：不应用 `excluded_dates` 的基础应排餐日期，用于前端展示可恢复餐次。
- `customerScheduleDays`：同一个客户的早餐和午晚餐排餐日期合并结果，用于页面每个客户一个“排餐日历”按钮。
- `baseMealTypes`：该日期来自订单基础排餐规则的餐次。
- `excludedMealTypes`：该日期被 `customer_profile.exclude_dates` 取消的餐次。
- `addedMealTypes`：该日期来自 `customer_meal_schedule_addition` 的人工新增餐次。
- `scheduledMealTypes`：该日期已生成排餐记录的餐次，前端在对应餐次标签上显示勾选标记。
- `mealScheduleCells`：新增的午晚餐数量日历数据，按订单、日期和餐次拆分；同一客户的行返回相同网格数据。
- `mealScheduleCells[].baseQuantity`：排除日期和人工数量覆盖前的基础份数，匹配订单送餐规则时为 1，否则为 0。
- `mealScheduleCells[].quantity`：当前目标份数。排除日期优先为 0；无人工覆盖时等于基础份数。
- `mealScheduleCells[].soupQuantity`：目标份数中显式含汤的份数；`null` 表示沿用订单配置。`defaultIncludesSoup` 标明订单是否配置汤品。
- `mealScheduleCells[].generatedCount` / `verifiedCount`：当前有效生成份数与已核销份数。
- `mealScheduleCells[].failedCount`：当前有失败原因的结果份数，可重生。
- `mealScheduleCells[].manualOverride` / `excluded`：是否有人工数量覆盖、是否被客户排除日期覆盖。
- `mealScheduleOrders`：数量日历的订单摘要，包含餐次、首日餐次、午晚餐/早餐购买和剩余份数、日期范围及订单状态；同一客户多订单时用订单ID区分网格行。
- `manualScheduleAdditions`：当前月份已保存的人工数量覆盖，包含原绑定订单ID；新页面保存时保留订单绑定及含汤数。
- `customer-meal-stats` 查询返回仍有余额的进行中（1）和暂停（4）订单；暂停订单的网格只显示来源计划与“待通知”，保存数量时仅允许进行中订单。
- `calendarRevision`：客户整份排除日期及当前月份数量覆盖的修订标记，保存数量网格时原样回传。

### 计算规则

- 按 `statsMonth` 展开当月日期，并限制在订单 `start_date` 到 `end_date` 范围内。
- 若日期等于 `start_date`，按 `start_meal_type` 过滤未开送餐次。
- 按订单 `meal_type` 过滤餐次。
- 按订单 `schedule_mode` 过滤日期：`DAILY` 每日，`WEEKDAY` 工作日，`WEEKEND` 周末，`SCHEDULE` 按 `delivery_dates` 中的日期和餐次。
- 按客户档案 `excluded_dates` 排除指定日期和餐次。

## customer-meal-schedule-adjustments

保存客户排餐日历调整。该接口不会补生成增加的份数；目标份数减少时会清理多余的未核销结果行。

### 请求

```
PUT /api/customerProfile/mealStats/scheduleAdjustments
```

### 请求体

```json
{
  "customerId": 1,
  "statsMonth": "2026-04",
  "quantityMode": true,
  "expectedRevision": "sha256-hex",
  "excludedDates": [
    { "date": "2026-04-02", "mealTypes": ["DINNER"] }
  ],
  "additions": [
    { "orderId": 1001, "date": "2026-04-05", "mealType": "LUNCH", "quantity": 2, "soupQuantity": 1, "remark": "临时加餐" }
  ]
}
```

### 响应

```json
{
  "customerId": 1,
  "excludedMealCount": 1,
  "additionMealCount": 1,
  "deletedUnverifiedPlanCount": 1
}
```

`additionMealCount` 表示本月保留的正数数量覆盖单元格数；`deletedUnverifiedPlanCount` 合计表示本次因排除日期或份数下调而删除的未核销结果行数。

### 规则

- `excludedDates` 和 `additions` 都按页面保存后的完整列表提交。
- 数量网格请求设置 `quantityMode=true`；显式提交 `quantity` / `soupQuantity` 或 `expectedRevision` 也会启用数量网格校验。旧调用方省略这些字段时按旧单份操作处理。
- 数量网格必须回传 GET 响应中的 `calendarRevision` 到 `expectedRevision`；标记过期时服务端返回“排餐日历已被其他人修改，请刷新后重试”。
- `additions[].quantity` 为正整数，缺省按 1 份处理；`additions[].soupQuantity` 可为空，为显式值时必须在 0 到目标份数之间。0 份使用 `excludedDates` 表达。
- 数量网格保存会拒绝将目标份数调低到已核销份数以下，并校验当前月份计划不超过扣除其他日期已核销和已生成未核销记录后的订单可用份数。
- `statsMonth` 为当前编辑月份，格式 `yyyy-MM`；后端只同步该月份内的人工新增记录，避免保存单月日历时影响其他月份。
- 新增排除餐次时，如果已有未核销排餐记录，会同步软删除该客户排餐记录、菜品明细和手工换菜关系；减少正数份数时，只删除超出目标的未核销份数。
- 新增排除餐次时，如果已有已核销排餐记录，接口返回包含具体日期和餐次的错误信息，不更新日历状态，例如 `2026-04-02 晚餐已核销，不能取消排餐`。
- `deletedUnverifiedPlanCount` 合计返回因排除日期和份数下调而软删除的未核销结果行数。
- `additions` 必须绑定当前客户的进行中订单，且订单餐次类型需包含目标餐次。后端会校验目标日期在订单有效期内；当前端默认订单不覆盖目标日期时，会自动改绑到同客户同餐次且覆盖目标日期的进行中订单。
- `excludedDates` 优先级高于 `additions`。
