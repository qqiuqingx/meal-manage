# 智能排查助手统一聊天接口文档

## 1. 接口定位

客服聊天统一由主系统会话服务进入 Agent 的 LLM Tool Calling 链路。普通业务查询和排餐问题使用同一个聊天入口；Agent 只调用当前客服有权限使用的只读工具，实时业务事实必须来自本轮成功工具结果。

排餐、客户、订单、核销、退餐、套餐、菜品和运营指标工具的内部接口与权限见《智能客服Agent内部业务查询接口文档》；本接口不再提供单独的直连诊断方法。

## 2. 聊天接口

- Path：`/api/agent/meal-plan/chat`
- Method：`POST`
- Permission：`agentDiagnosis:list`
- Header：可选 `X-Request-Id`

### Request

```json
{
  "sessionId": "session-001",
  "clientMessageId": "message-001",
  "message": "B2200 今天午餐排了什么？"
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | string | 否 | 不填写时由主系统创建会话 |
| `clientMessageId` | string | 否 | 客户端消息幂等键 |
| `message` | string | 是 | 客服自然语言问题 |

会话上下文、工具白名单、数据范围和内部访问令牌由主系统服务端生成，前端不得提交或覆盖。

缺少条件时返回澄清状态，例如：

```json
{
  "status": "NEED_MORE_INFO",
  "assistantMessage": "请补充要查询的餐次。",
  "missingSlots": ["MEAL_TYPE"],
  "quickReplies": ["早餐", "午餐", "晚餐"],
  "cards": [],
  "partial": false
}
```

主要字段：

| 字段 | 说明 |
| --- | --- |
| `status` | `ANSWERED`、`NEED_MORE_INFO` 或 `ERROR` |
| `assistantMessage` | Agent 经过最终回答护栏校验的文本 |
| `missingSlots` | 仅由 Agent 明确返回的待补充条件枚举：`CUSTOMER_OR_ORDER`、`RECORD_DATE`、`DATE_RANGE`、`MEAL_TYPE`、`PACKAGE`、`RULE_TOPIC`；`ANSWERED` 时为空数组 |
| `quickReplies` | 主系统按 `missingSlots` 生成的固定快捷回复，最多 6 项、每项最多 20 个字符；不接受模型自定义按钮文本 |
| `facts` | 可追溯的工具事实摘要 |
| `cards` | 与当前问题相关且经过语义去重的成功工具业务卡片 |
| `presentations` | 与卡片关联的受控展示描述，只包含视图、布局和字段引用；主系统透传并持久化，不解释业务 |
| `toolFacts` | 工具名称、调用标识和安全结果摘要 |
| `toolTraceSummary` | 调用状态、结果数量等脱敏追踪信息 |
| `warnings` | 权限不足、空结果、截断或工具失败等稳定告警 |
| `partial` | 是否只返回部分结果 |
| `conversationPatch` | 主系统版本校验后持久化的会话摘要 |

`presentations` 与 `cards` 按 `sourceToolCallId` 关联。主系统会话详情在每条消息的
`businessResult.presentations` 中保留该快照，并同时提供消息顶层 `presentations` 便利字段；旧消息缺少该字段时返回空列表，不重新调用 Agent 或业务查询。

### `presentations` 展示契约

展示描述只保存安全字段路径和展示语义，不保存业务值、HTML、Markdown、表达式、组件名或 ECharts option。v1 字段约束如下：

| 字段/对象 | 约束 |
| --- | --- |
| `schemaVersion` | 只能为 `v1` |
| `decisionSource` | 只能为 `SYSTEM` 或 `LLM`；当前 11 类已知卡片使用 `SYSTEM` |
| `layout` | 只能为 `TABS` |
| `availableViews` / `defaultView` | 视图只能为 `TEXT`、`TABLE`、`BAR`、`LINE`、`PIE`，默认视图必须在列表中，最多 5 个且不可重复 |
| `format` | 只能为 `TEXT`、`DATE`、`DATE_TIME`、`STATUS`、`MEAL_TYPE`、`NUMBER`、`BOOLEAN` |
| `title` / 标签 | 普通文本；标题最多 100 个字符，字段标签最多 30 个字符 |
| `table` / `sections` | 每处表格最多 20 列，详情 sections 最多 8 个且只允许一层 |
| `chart.metricFields` | 最多 4 个数值指标；BAR/LINE 最多 50 个类别，PIE 最多 8 个类别 |

服务客户卡片的固定列顺序为：

```text
客户编号 | 姓名 | 订单编号 | 下单时间 | 订单状态 | 套餐
```

其中 `customerCode` 是主标识，`customerName` 只在已认证且完成业务权限/数据范围校验的内部 Agent 链路中受控返回；`orderTime` 按成交时间优先、创建时间回退确定。普通客户页面和非 Agent 接口不因本响应改变姓名策略。

### 展示降级与历史兼容

- 已知卡片由系统规则生成展示描述，不调用展示规划 LLM；未知卡片才提交不含业务值的字段结构给独立规划器。
- 规划器不可用、超时、建议非法或校验失败时，当前卡片降级为安全表格、键值摘要或“展示格式暂不可用”，并增加 `PRESENTATION_RULE_MISSING`、`PRESENTATION_FALLBACK_APPLIED` 等稳定告警；不丢弃 `assistantMessage`、`cards` 或其他卡片。
- `truncated=true`、`partial=true` 或影响完整性的查询告警时，前端隐藏图表，保留表格/摘要和原始业务告警；展示告警本身不改写业务 `partial`。
- 图表字段路径非法、数据为空或 ECharts 初始化失败时，只移除该图表视图并回退到表格/摘要；所有视图无效时显示“展示格式暂不可用”，不能解释为查询无结果。
- 新会话在 `businessResult.presentations` 中保存原展示决策并直接恢复。旧 cards-only 消息由前端只读兼容映射处理，旧 `maskedName` 保持原值，不重新查实时数据或调用 LLM。

第一期卡片类型包括：

- `CUSTOMER_PROFILE_LIST`
- `SERVICE_CUSTOMER_LIST`
- `SERVICE_CUSTOMER_DETAIL`
- `MEAL_PLAN_LIST`
- `VERIFICATION_LIST`
- `REFUND_LIST`
- `DISH_LIST`
- `DISH_CANDIDATE_LIST`
- `PACKAGE_DETAIL`
- `METRIC_RESULT`
- `BUSINESS_RULE`

金额、价格、完整手机号、完整地址、Token、权限集合、数据范围规则和内部关联 ID 不在客服默认卡片中展示。Agent 不执行写操作，也不得在回答中声称已下单、已排餐、已退款或已核销。

## 3. 会话管理

会话列表、创建、详情、归档和标题更新接口继续使用 `/api/agent/chat-sessions/**`，由当前登录客服的数据权限隔离。消息幂等、会话版本冲突和最近工具摘要由主系统会话服务处理。

### 3.1 会话列表

`GET /api/agent/chat-sessions` 支持以下查询参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `keyword` | string | 空 | 服务端匹配标题、客户编号和最近摘要；前端输入使用 300ms 防抖 |
| `archived` | boolean | `false` | `false` 查询进行中会话，`true` 查询归档会话 |
| `page` | integer | `0` | 从 0 开始的页码 |
| `size` | integer | `20` | 前端固定每页 20 条，服务端最大 100 条 |
| `customerId/customerCode` | number/string | 空 | 可选的客户过滤条件 |
| `recordDateStart/recordDateEnd` | string | 空 | 可选日期过滤，格式 `yyyy-MM-dd` |
| `mealType` | string | 空 | 可选 `BREAKFAST/LUNCH/DINNER` |

响应沿用主系统 `PageResult`：

```json
{
  "content": [
    {
      "sessionId": "session-001",
      "title": "B2200 午餐排餐",
      "customerCode": "B2200",
      "lastSummary": "已查询排餐记录",
      "lastMessageTime": "2026-08-05T12:00:00.000+08:00",
      "archived": false
    }
  ],
  "totalElements": 21
}
```

列表、详情、归档/恢复和标题更新均只允许当前客服操作自己的会话。归档使用
`PUT /api/agent/chat-sessions/{sessionId}/archive?archived=true`，恢复使用同一路径传
`archived=false`；归档详情可以读取历史快照，但聊天和重试会被拒绝，恢复后才可继续发送。

### 3.2 创建与恢复兼容

`POST /api/agent/chat-sessions` 是可选的显式创建接口。聊天接口不传 `sessionId` 时，主系统在首条消息处理时懒创建会话；前端“新建会话”只重置本地工作区，不会因为点击按钮产生空会话。

历史消息可能没有 `presentations`、`missingSlots` 或 `quickReplies`。主系统和前端以空数组/旧 cards-only 只读映射兼容，直接使用已保存的业务快照，不重新调用 Agent 或实时业务查询；旧 `maskedName` 保持原值。

## 4. 失败与部分结果

- `ANSWERED`：返回已完成的事实结论或兼容旧版纯文本答复，`missingSlots` 必须为空。
- `NEED_MORE_INFO`：明确要求客服补充查询条件，可没有成功工具事实；必须至少返回一个受控 `missingSlots`，不得声称已取得实时查询结果。
- `ERROR`：模型、工具、权限或安全护栏失败；响应不透传 SQL、内部 URL、堆栈或下游原始异常。
- `partial=true`：至少一个工具失败、结果被截断或详情字段不完整；模型不得将部分结果表述为全部数据。

安全边界：Agent 对外响应、cards、presentations、前端和日志不包含原始/完整手机号、地址、金额、Token、权限集合、SQL 或内部关联 ID。内部 ID 只在主系统关系校验和工具间关联阶段作为不透明键使用，离开该阶段前移除。
