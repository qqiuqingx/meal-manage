## 实施步骤
1. 保持月份页解析闭环，新增按名称读取客户禁忌Sheet；验证C～G列映射及表头和数据起始位置，异常时提供可见提示或结构错误，避免静默错列。
2. 按B优先、否则A关联月份页有效编号，不继承空编号；标题、说明行、图片不当作客户文字。缺少该Sheet时保留原导入能力。
3. 批量加载五类字典，以整名优先、分隔词项与有限前缀规则匹配。记录稳定来源键、词项与候选；不同类型或同类型重名均不随意择一。
4. 保留完整原文块后再拆词匹配，草稿分别展示原文与匹配对象；未匹配文字、无法关联客户的行、歧义项分别提示。多行匹配对象按类型ID合并，原文按完整文本块去重。
5. 扩展确认接口接收摘要和人工选择；服务端重算候选，校验未知来源键、重复键、伪造类型ID、未解决歧义与字典变化。所有选择校验完成后才开始写入。
6. 新建客户随同原客户事务写入结构化字段和原文块；失败回滚该客户。已有客户仅同编号同手机号允许合并补录，锁行后再次校验身份，定向更新结构化字段、原文块和审计信息，不创建订单。
7. 无匹配或人工跳过仍保存非空原文；图片与空值不生成原文块，仅原文有新增也计为补录。结果区分CREATED/UPDATED/ALREADY_EXISTS/SKIPPED/FAILED，统计新增、补录、无变化、异常；原有餐数与首单校验维持原逻辑。

## 验证方式与完成标准
- 新旧编号同时有值、新编号不存在不回退、空编号、不匹配客户、重复行、缺少Sheet。
- D不吃描述仍进想吃，E喜欢描述仍进禁忌；图片跳过；文字零匹配提示且原文持久化。
- 部分匹配、全部未匹配、人工跳过均保留完整原文；事务失败原文与关联一起回滚；重传不重复追加原文块。
- 五类唯一匹配、同名多类型、同类型重名、多选、显式跳过、未选择阻止提交。
- 字典改变、选择键重复或伪造、非法JSON拒绝且尚未写库。
- 已有客户补录、身份冲突、重传无重复、空白不清空、补录不改订单。
- 原有导入Parser/Flow回归通过，使用匿名工作簿与Mock，不清业务表。
