# 批量导入配送电话保留

## 背景与目标

客户批量导入目前只读取地址列的第一个电话标签。电话列与地址列号码不一致时，两者须分别保存；地址列存在多条配送电话时须全部保留，编辑客户后不得丢失。

## 影响范围

- 客户主档新增可空 `delivery_phone_info` 文本字段，保存地址列电话标签的全部原文值；原 `phone` 继续保存电话列的客户手机号。
- 地址 `contact_phone` 仍作为单值联系电话，取首个可用配送电话；没有配送电话时回退客户手机号。订单、排餐和其他地址字段含义不变。
- 客户详情与创建/编辑接口增加可选 `deliveryPhoneInfo` 字段；旧调用方不传时保持已有值。
- 批量导入预览继续只展示脱敏的单值地址联系电话，不返回完整配送电话文本。

## 规则来源与实施约束

- 已读取 `/Users/qqx/.codex/AGENTS.md`（用户级）与仓库根目录 `AGENTS.md`（项目级）；目标目录下未发现更具体规则。
- 保留无关未提交改动；不提交、不执行数据库迁移；提供可执行的增量 SQL。
- 沿用 Java 8、Spring Boot 2.7、MyBatis-Plus 与现有 DTO；不新增依赖。实体字段添加业务注释，修改方法补齐用途与参数说明。
- 电话列仍按现有手机号规则校验；配送电话原文不拿来替代客户手机号，也不因号码不同阻止导入。
- 后端只运行受影响模块及相关测试，前端只检查修改文件；不连接数据库。

- 已检查 `CustomerProfileServiceImpl` 的详情、创建、编辑路径及 `CustomerProfileMapper.xml` 的结果映射；地址联系电话由现有地址实体承载单值。
