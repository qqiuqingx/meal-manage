- 环境无法提供实际 API/浏览器/数据库验证时如实列明，不能用单元测试替代这些验证结论。

## 实施步骤

1. 在可用开发环境核验矩阵页和主档列表均使用同一功能，验证输入后配料可见、可编辑、可删除，保存后重开结果一致。
2. 对历史菜品核验打开/仅改名称/直接保存不识别，修改制作流程才追加。原关联及用量、备注保留；清空全部配料后展示文本与配料列表同步为空。
3. 核验在途识别、快速保存、取消、关闭重开和识别失败场景；确认没有后台历史识别或字典新建副作用。
4. 文档记录只读识别接口、权限、长度限制、响应空用量、启用配料/调料规则、历史触发边界、人工排除会话范围、字符规整及不支持同义词/烹饪语义推断的限制。
5. 汇总已通过验证，仅对后续改动或尚未覆盖的风险补充检查。执行 `git diff --check`，检查本次文件和接口文档链接；不默认全量构建或启动无关服务。

## 验证方式

复用 Phase 01/02 的实际测试结果，按下表记录可用环境中的页面/API/保存重读验证。检查文档与接口的字段、权限和异常行为一致，执行 `git diff --check`；新增且未跟踪的文档使用 `git diff --no-index --check /dev/null <文件>` 检查。没有实际环境的用例明确标为未验证，不为了验收扩大部署范围。
