# Phase 02 排餐与统计口径

## 执行前规则检查

核对当前规则链及排餐、客户统计、订单和核销业务文档。

## 目标

历史基数计入午晚餐餐数池，未来计划仍可按剩余数排餐和核销。

## 前置依赖

依赖 Phase 01 的 `imported_verified_count` 字段及导入计算契约；需读取其交付记录。

## 本阶段实施约束

普通订单历史基数为 0，行为保持一致。导入前餐次不制造逐餐日志；退款、日历、统计不能把历史基数当未来可用餐数。

## 涉及文件与步骤

- 更新午晚餐池剩余计算、客户统计与日历数量上限，扣除导入历史基数。
- 审核订单编辑时 `remaining = total − verified`，保留导入基数；核销后 `verified_count` 正常增 1。
- 更新退餐按餐次可退数量的计算，避免历史餐数被当作未消费份数。
- 增补受影响服务的回归测试。

## 验证方式与完成标准

未来 4 份可排餐、核销；历史 3 份不重复排餐；普通订单回归通过。

## 状态

complete

## 阶段交付记录

- 排餐数量上限、午晚餐池预警、客户日历/统计、个人档案剩余餐数和退餐数量均扣除 `imported_verified_count`，普通订单默认 0 不变。
- 订单编辑保留已导入历史基数；编辑请求省略已核销数时沿用现值，不允许降至历史基数以下。导入后真实核销仍按原事务逐份增加 `verified_count` 并扣减 `remaining_count`。
- 导入订单若已全部历史核销且未暂停，创建为已完成状态；其余仍按进行中/暂停处理。
- 新增日历、餐数池预警、订单列表/编辑、客户档案汇总和退餐回归测试，定向测试通过。
