# Phase 01 来源餐数与订单写入

## 执行前规则检查

核对当前用户级、仓库级 AGENTS.md 与客户、订单业务文档；确认目标目录无更具体规则。

## 目标

让导入订单的午晚/合计、历史核销和剩余餐数同时符合来源表及未来日格。

## 前置依赖

无。输入为工作簿解析结果和当前导入服务；输出为 `imported_verified_count` 持久化契约。

## 本阶段实施约束

早餐行不计入购买数；无效公式仍按原规则阻断；不生成假的核销日志；不修改普通订单创建行为。

## 涉及文件与步骤

- 更新解析器午晚餐购买数及导入草稿计算，拒绝购买数小于未来可用数的不一致行。
- 为 `customer_order` 提供可空/默认 0 的导入历史核销基数字段、实体与 Mapper 映射，新增增量 SQL。
- 写入订单购买数、导入历史基数、已核销数与剩余数，开始日期与未来日格边界对齐。
- 加匿名回归样例验证 7/3/4 及早餐续行。

## 验证方式与完成标准

定向 Maven 测试覆盖预览和实际写入路径；`git diff --check` 通过。记录字段契约、SQL 执行前置与实际改动。

## 状态

complete

## 阶段交付记录

- 午晚餐明细的 I 列按客户汇总，早餐续行不计入购买数。导入草稿购买数取该汇总，历史基数取 `I − (J + 导入日后日格)`；负值视为来源公式不一致。
- `customer_order.imported_verified_count` 默认 0；导入写入时同时设 `lunch_dinner_count=I`、`verified_count=imported_verified_count`、`remaining_count=I-imported_verified_count`。订单开始日期设为导入次日。
- 已增加基础 DDL、增量 SQL、实体与 Mapper 映射；SQL 未执行。
- 匿名回归样例覆盖购买 7、历史 3、剩余 4 和早餐续行；定向 Maven 测试通过。
