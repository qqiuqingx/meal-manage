## 目标

正式确认后按客户独立事务创建档案、地址、首单和未来逐餐数量，合规客户成功、异常客户有可重试结果。

## 前置依赖

- 本计划 Phase 01/02 完成；外部依赖 customer-meal-calendar-quantity Phase 01/02 完成并提供数量保存/逐份排餐契约。

## 输入与输出

- 输入：原 Excel 文件、Phase 01 预览哈希、实际导入日期、数据库当前套餐/编号占用与日历数量服务。
- 输出：每位客户的创建/跳过结果、客户 ID/订单 ID 和未来日期计划；不产生历史核销记录。

## 本阶段实施约束

- 每位客户单独事务，失败仅回滚该客户新建的档案、地址、订单、未来计划；绝不更新其他业务客户或全表清理。
- 服务端重新解析文件并比对哈希，不相信前端回传的餐数/状态；编号池锁定与重复判定要覆盖并发导入和手工新增。
- 0 金额是明确业务值，核销时允许合法 0 单价并继续原子扣餐数；负数/无效金额仍拒绝。
- 不写旧客户禁忌表；不把原始 Excel 留在项目目录或日志。

## 实施步骤

1. 增加需授权的提交入口，接收原文件、预览哈希和导入日期；重跑解析、校验公式/日期/套餐/编号池/数据库状态。导入日期为订单 startDate；失效源快照拒绝提交。
2. 重用客户建档及首单真实生产校验，必要时抽出供普通建档和导入共用的创建服务，并返回生产所需客户/订单 ID。按确认编号生成姓名和地址联系人，金额/单价 0、早餐 0、已核销 0。
3. 对 E/F“等通知”写 PAUSED(4)，否则 ACTIVE(1)；H 明确餐次写系统枚举，未指定“等通知送餐”保留 null。相同客户多行合并为一笔首单，午晚餐数按 J+未来份数汇总。
4. 写入 9 月 25—30 日明确的日期/餐次/份数覆盖。B596 写目标 2 份、含汤 1 份；暂停单也保存来源计划，但状态 4 阻断实际排餐。
5. 允许 0 单价核销，每条已生成份独立扣 1 餐。针对跳过的坏电话、缺地址、撞号、套餐/编号池不匹配及事务失败返回行号/原因；同文件再次提交不重复创建已导入客户。
6. 验证每位客户事务边界、重试/并发、暂停状态、B596 双份、0 元核销与正常一份；同步接口和业务文档。
