# Phase 03 排餐生成与日历对齐

## 执行前规则检查

重新读取适用 AGENTS.md、排餐/核销业务说明和排餐生成接口文档。

## 目标

生成排餐时仅选中日历计划份数大于 0 的订单日期餐次，并保持现有已生成/核销保护。

## 前置依赖

Phase 01 暂停字段与 Phase 02 可复用计划计算已经完成；读取两阶段交付摘要及方法契约。

## 输入与输出

输入：日期、餐次、候选订单、客户排除与有效数量覆盖。输出：生成结果与日历份数一致的候选过滤及回归测试。

## 本阶段实施约束

暂停订单不可生成；超过购买池顺序截止日期不可生成；人工加餐仍受购买池上限和订单状态约束。已核销行不得删除，重生只清理未核销行。不可仅修改展示。同步排餐接口/业务文档。

## 涉及文件

`MealPlanServiceImpl.java`、相关 Mapper/测试、`eladmin/doc/apidoc/排餐计划生成接口.md`、`eladmin/doc/business/排餐管理业务说明.md`，按实际依赖最小修改。

## 实施步骤

1. 候选订单过滤复用 Phase 02 日期餐次计划，不重复实现购买池算法。
2. 验证截止日、截止后、暂停前后、人工覆盖、已生成及重生路径。
3. 汇总前后端和 Maven 验证，检查旧接口/数据库兼容及工作区 diff。

## 验证方式与完成标准

Java 8/Maven 定向测试、前端测试、必要的本地接口核验和 `git diff --check`；日历为 0 的日期不再生成，原有已核销记录与其他订单不受影响。完成后记录全部交付和验证结果。
