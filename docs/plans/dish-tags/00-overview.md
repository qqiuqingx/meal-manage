## 弹窗交互与保存边界

在现有菜品弹窗基本信息区增加“菜品标签”区域，使用菜品专用子组件承载，避免继续扩大主表单。

1. 展示已选标签；“×”只从当前表单移除绑定，不删除字典。
2. 展开标签选择区，支持搜索、分页/加载更多和勾选已有标签，已选标签不因搜索或换页丢失。
3. 搜索无匹配时提供“新增标签”，提交成功取得 ID 后自动加入当前表单选择；名称去首尾空白、非空、最长64字符，重复名称显示明确错误。
4. 同一区域内每个字典选项提供“重命名”和“删除标签”，使用内联编辑及确认提示，不跳转路由、不新增独立标签管理页面。未绑定的标签也能搜索和管理。
5. 重命名提示“修改会影响所有使用该标签的菜品”；删除字典仅在没有任何已保存菜品引用时允许。仍被当前菜品引用时，提示先移除并保存菜品，再删除字典；不自动解绑其他菜品。
6. 字典新增、重命名、删除即时保存；菜品绑定随“保存菜品修改”提交。固定提示“标签字典操作立即生效；标签选择在保存菜品后生效”。取消菜品弹窗丢弃绑定变化，但不会撤销已完成字典操作，新建未使用标签可以删除。
7. 删除未使用字典标签成功后清理本地已选项；重命名同步更新本弹窗选项和已选展示，其他菜品再次读取显示新名称。请求失败保留输入、阻止重复点击。
8. 新增菜品没有 ID 时同样可维护字典和选择标签，最终创建菜品并保存关联在一个事务完成。

不为了外观相似立即抽取配料公共组件：现有配料 tagManager.vue 是独立管理弹窗且绑定配料权限，本需求需要内嵌编辑。优先复用既有 Element UI、请求与权限工具，保持两个业务模块独立。

## 跨阶段接口契约

| 接口 | 请求/响应 | 权限 |
| --- | --- | --- |
| GET /api/dish-tags | name/page/size，返回 {content,totalElements}，条目含 id/name/createTime/updateTime | dish:list/add/edit 任一 |
| POST /api/dish-tags | {name}，201 返回含生成 id 的对象 | dishTag:add |
| PUT /api/dish-tags | {id,name}，204 | dishTag:edit |
| DELETE /api/dish-tags/{id} | 无引用才删除，200；有引用或不存在返回400 | dishTag:del |
| POST/PUT /api/dishes | 增加可选 tagIds: Integer[]，原状态码不变 | 原 dish:add/edit |
| GET /api/dishes/{id}、GET /api/dishes | 增加 tagIds 与 tags: [{id,name}]，无标签为空数组 | 原 dish:list |

新增菜品 tagIds 未传/null/[] 都不绑定；编辑未传/null 保持，[] 清空，非空整体替换。ID去重，null元素、非正数或不存在ID返回400，菜品及关联整体回滚。删除菜品清理该菜品的标签关系，保留标签字典。

独立按钮权限 dishTag:add/edit/del 挂到已核实的菜品管理菜单，不增加页面菜单、不默认赋权；管理员沿用项目约定。普通菜品编辑者可绑定已有标签，不因能编辑菜品自动获得全局字典修改权。

服务端按菜品锁串行化同一菜品的关系替换和删除；按标签ID升序锁定待绑定标签，标签删除/改名使用相同标签行锁，删除在锁内检查引用。保留原有菜品更新行为，避免影响配料关系；列表批量加载标签避免 N+1。

## 风险与回滚

字典即时保存与菜品保存不同，必须展示提示并覆盖取消场景；共享范围仅为所有菜品，改名影响范围需要确认提示。并发删除与绑定必须使用同一锁协议，并用真实 MySQL 场景验证。现有列表/详情 getById 路径较多，只对已约定维护接口保证标签返回，不扩展排餐契约。

部署顺序：新增表及按钮权限 SQL → 后端 → 前端 → 按角色赋权并验收。SQL 幂等，菜单缺失给出可诊断结果，禁止创建错误根菜单。回滚应用版本时保留新增表及数据，不自动 DROP 或清表，旧版本忽略新表；权限菜单如需移除只限定本次创建记录。没有实际执行测试或发布前不得报告通过。
