# 菜品标签发布与回滚清单

状态：实现与单元验证完成；未执行数据库脚本、未部署、未向角色授权。真实 MySQL 验收需在确认隔离测试库后单独执行。

## 发布顺序

1. 先备份目标库，并确认 `DB_NAME` 指向隔离测试库。执行 `eladmin/sql/20260928_dish_tag.sql`；核对两张表、`utf8mb4_unicode_ci` 唯一索引、菜品管理父菜单下的 `dishTag:add/edit/del` 按钮权限。重复执行一次确认不产生重复菜单或表。若脚本报告未找到 `dish:list` 菜单，停止后核实菜单数据，不创建新页面或根菜单。
2. 记录脚本新增的三个 `sys_menu.menu_id`，并确认脚本没有写入角色菜单授权。
3. 部署后端，再部署前端；回退应用版本时保留表及字典数据。
4. 通过系统角色授权流程，只给负责字典维护的角色分配 `dishTag:add/edit/del`。普通菜品编辑者继续使用 `dish:add/edit` 绑定已有标签。不要默认赋权。
5. 按下方验收项验证矩阵页和菜品主档列表两个入口。验收未完成前不评估生产部署。

## 数据库与并发验收

确认隔离测试库已执行部署 SQL，且仅配置该测试库的 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PWD` 后，再运行：

```bash
mvn -pl eladmin-system -am \
  -DdishTag.mysql.integration=true \
  -DdishTag.mysql.testDatabase=true \
  -Dtest=DishTagMySqlIntegrationTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

该测试使用随机测试标签名，清理时按本次生成的菜品ID和标签ID限定范围。完成后确认关系、菜品和无引用测试标签均无残留。禁止用全表删除清理测试数据。

## 验收项

| 项目 | 预期结果 |
|---|---|
| 搜索、分页选择和回显 | 已选标签跨搜索和翻页保留；菜品详情及分页列表均返回 `tagIds`、`tags`，无标签返回空数组 |
| 新增、编辑和取消 | 新增标签即时写字典并进入待保存选择；菜品取消只丢弃绑定变化；编辑未传/null 保持、空数组清空、非空整体替换 |
| 字典改名 | 二次确认说明影响范围；改名后当前弹窗立即显示新名称，其他菜品再次查询显示新名称 |
| 字典删除 | 未引用标签可以删除；仍被引用时拒绝；已保存的当前菜品引用需要先移除并保存再删除 |
| 校验和事务 | 空名称、超过64字符、重名和无效标签ID返回业务错误；无效绑定不留下菜品或关联半成品 |
| 并发 | 同一菜品两次并发替换只留下完整的一组标签；标签删除与绑定并发最多一方成功，不能留下孤立关系 |
| 权限 | 菜品新增/编辑者可读和绑定已有标签；无 `dishTag` 写权限的普通用户不能新增、改名或删除；管理员及授权角色按配置可执行 |
| 模块独立 | 菜品标签与配料标签可重名；一侧改名或删除不改变另一侧；标签不参与排餐、忌口或配料过滤 |

## 回滚

- 应用异常时回退到部署前的后端和前端版本，保留两张菜品标签表和用户创建的数据，旧版本会忽略新表。
- 如需撤下按钮权限，先使用记录的三个菜单ID核对 `sys_role_menu` 是否已有授权；仅处理本次新增的权限记录，不批量删菜单、不改现有菜品菜单权限。可先隐藏按钮记录，确认无角色依赖后再按记录ID清理。
- 不自动 `DROP TABLE`、不清空字典或关系数据。若要删除标签数据，需另行确认引用范围并按具体主键处理。
