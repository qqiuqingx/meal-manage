## 数据与接口契约（本计划的实施默认值）

### 数据模型

- `dish_ingredient_tag`：id INT 自增、name VARCHAR(64) 非空唯一、create_time/update_time DATETIME。名称 trim 后保存，空白和超长拒绝；唯一性使用明确的 utf8mb4_unicode_ci 规则（英文大小写不区分），数据库唯一键兜底并转为友好错误。不引入同义词规范化算法。
- `dish_ingredient_tag_relation`：ingredient_id INT、tag_id INT，联合主键 `(ingredient_id, tag_id)`，索引 `(tag_id, ingredient_id)`。不冗余标签名。
- 不增加启停、层级、别名、颜色或自动打标；标签可先创建而没有配料。
- 删除正在使用的标签返回业务错误；未使用标签允许删除。删除配料时同事务删除其标签关系，保留标签字典。停用配料保留标签。

### API

- 新建 `/api/dish-ingredient-tags`：GET（name 模糊查询，page=0、size=20，返回 content/totalElements）、POST `{name}`、PUT `{id,name}`；DELETE `/{id}`。新增返回创建对象（包含 id），其他状态码沿用已有控制器约定。
- 标签权限 `dishIngredientTag:list/add/edit/del`。标签 GET 也允许已有配料 list/add/edit 权限用于选项加载；标签维护页及写接口要求各自标签权限。
- 现有配料 POST/PUT 增加可选 `tagIds`；响应统一增加 `tagIds: []`、`tags: [{id,name}]`，列表、详情及按菜品查询保持一致。
- 新建未传/null/空数组均表示无标签；编辑未传或 null 表示保持原标签，`[]` 表示清空，非空数组表示整体替换。数组重复 ID 去重，无效/不存在 ID 拒绝；写入和配料保存必须同事务。
- 配料查询增加可选 `tagId`（一次筛一个标签，与其他筛选条件 AND）；用 EXISTS 避免多标签导致分页重复。配料导出遵循同样筛选，增加标签名称列。
- 配料表单多选既有标签；标签在独立管理页创建/改名/删除，不在配料保存中隐式创建标签。选项使用分页远程搜索，选中项通过详情 tags 回填，防止首屏之外标签丢失。
- 并发保存同一配料时锁配料行，事务内替换关系；标签删除与绑定按标签 ID 升序锁标签行再检查引用，避免校验后删除导致悬空引用。无需新增版本字段。

## 验收与发布

新增两个标签 → 绑定同一配料 → 重新打开仍显示两个 → 移除一个 → 清空；标签可被多个配料复用。分类、菜品配料关系及原有编辑功能不变。一级改名仅肉类→肉禽蛋、调料→调味品、主食→粮油米面、坚果→干货坚果。
