## 实施步骤

1. 业务说明写明分类与多标签并存、标签复用、删除规则及本次不接入禁忌过滤；API 文档记录示例、null/[] 语义、权限和错误。
2. 定向检索确认旧同义词运行时入口和菜单脚本均移除；旧计划明确被替代，其他独立需求不会随旧计划自动执行。
3. 审查标签 SQL 的重复执行不会重复插菜单、不绑定环境 ID、不授权所有角色；确认没有 DROP 同义词表等无必要变更。
4. 一级改名默认预览，核对四项映射、来源缺失/目标冲突输出；执行者记录源 ID/旧名称后才打开开关，二级分类及配料归属完全保持。
5. 发布清单写明：测试环境执行新标签 SQL → 部署后端/前端 → 按现有流程赋标签权限 → 完整验收。一级改名作为独立可选步骤。数据库脚本执行需要目标环境授权，不因计划存在而直接操作生产。
6. 汇总覆盖新增、回显、修改、清空、复用、筛选、导出、删除保护、权限拒绝和原分类行为的证据。失败项修复到对应阶段后再更新状态。
7. 记录回滚应用版本及菜单 ID，保留标签数据；一级名称按已记录 ID 逐项恢复。不得生成全表清理脚本。
